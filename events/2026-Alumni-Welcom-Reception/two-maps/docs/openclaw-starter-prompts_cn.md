# OpenClaw 启动与引导提示词（中文）

## 1. 使用说明

- 本文件给技术引导员和现场管理员使用。
- 目标是让 AI 助手快速完成三类动作：
  1. 解释项目结构
  2. 引导小组修改地图
  3. 生成成果总结卡 `group_submission.json`

语义口径（请统一）：
- 地图 1（明途）= 人生路径图（家乡 -> 纽黑文 -> 现在）
- 地图 2（在地）= 城市地图（纽黑文 / 北京 / 上海）

## 2. 启动提示词（项目理解）

```text
你是活动现场的结对工程师。请先阅读当前仓库并输出：
1) 项目结构总览（入口、数据、样式、输出目录）
2) 最小可修改路径（改哪 1-2 个文件就能看到地图变化）
3) 20 分钟上手计划（每 5 分钟一个检查点）
要求：用非技术同学也能听懂的语言，不要输出过长代码。
```

## 2.1 分组破冰提示词（混合能力小组）

```text
你是小组协作教练。请根据我们组成员背景，快速输出：
1) 4 个角色分配（技术实现、叙事文案、在地信息、展示表达）
2) 每个角色 1 条“10 分钟内可完成”的任务
3) 如何让不懂网页开发的成员也能贡献可见成果
要求：语言简短，直接可执行。
```

## 3. 修改提示词（在已有地图上扩展）

```text
请在不破坏现有结构的前提下，帮我完成以下任务：
- 新增组员地图标记点（名称、角色、经纬度、简介、头像）
- 点击标记弹出信息卡（头像 + 文案）
- 按小组颜色区分标记
- 保留原模板数据，新增本组数据文件
最后请输出：
1) 修改了哪些文件
2) 每个文件改动原因
3) 如何快速回滚
```

## 4. 重做提示词（按主题新建变体）

```text
请基于现有 two-map 模板创建一个新主题变体，要求：
- 主题名：[填写主题]
- 至少 5 个示例点位
- 保留现有渲染链路
- 输出该变体的最小运行步骤
不要重构整个工程，只做最小可交付版本。
```

## 5. 总结卡提示词（group_submission）

```text
请根据我们小组当前成果，生成 submission/group_submission.json。
注意：
- 这是一份“成果总结卡”，不是原始数据全集
- 用一句话写清楚我们做了什么（what_we_built）
- key_changes 限制为 2-4 条具体变更
- deliverables 内写入真实文件路径
- 增加 member_elements 数组，写清每位成员的贡献元素
- 不要编造 demo_url
```

## 6. 现场管理员抓取提示词

```text
你是成果归档助手。请遍历所有可访问小组环境，读取：
- submission/group_submission.json
- submission/screenshot.png
输出：
1) 汇总表（group_id, group_name, map_theme, what_we_built, member_count, last_updated）
2) 异常清单（缺文件、字段缺失、截图缺失）
3) museum_index.json（用于项目博物馆渲染）
```

## 7. 现场口令（给每组）

- 先跑通，再美化。
- 不追求完整重构，先确保有可展示成果。
- 最后 15 分钟必须完成 `group_submission.json` + 截图。

## 8. 创意花活儿提示词（可直接复制）

### 8.1 叙事导演模式

```text
请把当前地图改造成“讲故事”版本：
- 用 3 个章节组织点位（起点、转折、去向）
- 每个章节给一句 20 字以内标题
- 点位弹窗增加“为什么重要”字段
输出一个 45 秒讲解提纲。
```

### 8.2 头像与关系网络模式

```text
请在地图中加入组员头像和关系线：
- 点位显示头像与角色标签
- 同主题点位用虚线连接
- 生成一个图例，解释颜色和线型
确保移动端也能看清。
```

### 8.3 新生任务闯关模式

```text
请把地图改成“新生 30 分钟上手挑战”：
- 设计 3 个任务点（文化、学习、社交各 1 个）
- 每个任务点含目标、建议时长、完成标记
- 最后生成一个“完成后你会得到什么”的总结卡。
```

### 8.4 风格化视觉模式

```text
请在不改动数据结构的前提下，做一版高辨识度视觉：
- 选择一种明确风格（例如报纸感、地铁导览感、明信片感）
- 统一颜色、图标、卡片样式
- 保留可读性优先，不要过度装饰
输出改动清单和设计理由。
```

### 8.5 京沪双城桥接模式

```text
请把当前地图扩展为“上海-北京双城桥接版”：
- 至少各添加 3 个上海点位与 3 个北京点位
- 每个城市给一个“校友推荐路线”
- 在弹窗里增加字段：给校友的提示 / 给非校友朋友的提示
- 最后输出一个 60 秒展示脚本（先上海后北京）
```

### 8.6 校友优先、朋友友好文案模式

```text
请优化当前地图文案，要求：
- 保留校友语境（耶鲁经历、行业路径、在地连接）
- 同时增加“第一次参加者也能看懂”的解释句
- 每张卡片不超过 3 行，避免信息过载
输出优化前后对照。
```

### 8.7 每个人都被看见模式（最终展示）

```text
请基于我们当前成果，生成一个“每个人都被看见”的展示版本：
- 为每位组员生成 1 个可见元素（点位/卡片/路线/文案）
- 在 group_submission.member_elements 里逐条记录
- 输出 60 秒展示台词，保证每位组员至少被提到一次
```
