# 火山引擎活动说明与初步资源设想

## 1. 这场活动在做什么

这是一次耶鲁校友活动中的现场共创环节。我们的目标不是做技术演示，而是让不同技术背景的人都能一起参与，并在现场做出可展示的成果。

参与者以校友为主，也有少量耶鲁朋友圈朋友。现场会先有分享和 Fishbowl 讨论，然后进入小组共创。

## 2. 现场流程是什么

活动中的共创部分大致分成 4 步：

1. **先分组**：我们会先根据大家的技术能力做混编分组，尽量保证每组里既有技术朋友，也有非技术朋友。
2. **先统一理解任务**：所有人先通过网页了解这次活动要做什么，理解两张地图：
   - 人生地图：看每个人从哪里来、在耶鲁经历了什么、现在在哪里。
   - 在地生活地图：看我们的城市（纽黑文、北京、上海）里有哪些值得记录的地点、路线和建议。
3. **再开始共创**：不懂网页开发的朋友也可以直接使用 OpenClaw 做快速可视化、生成创意、完善内容。
4. **最后展示**：每组会做一个最终展示，我们希望成果里能体现每一个人的元素；OpenClaw 也可以帮助大家想创意和整理展示方式。

## 3. 目前进展

这次活动更像一个面向混合能力人群的现场协作体验，而不只是一个单纯的技术部署问题。

我们这边已经准备好了两类前置材料：

- 完整可用的工程模板（two-map）
- 可直接使用的提示词包

目前已经有一套可以提前喂给 OpenClaw 的内容，方便双方一起判断是否适合做预配置、预演练和资源匹配。

## 4. 目前想到的两个资源方向

### 方向 1：20 组左右的开箱即用龙虾 / OpenClaw 环境

- 我们当前是按 20 组左右来估算规模。
- 按目前设想，最基础的 `2C4G` 算力起步应该就够用。
- 如果可以的话，最好是全流程网页即可使用。
- 理想状态下，每组有 1 个独立、开箱即用的环境。
- 这样现场参与者就不需要再做复杂安装或额外配置。
- 这里的“网页可用”最好包含网页预览能力，例如：
  - 主方案：直接提供开箱即用的网页预览服务；或
  - 退路方案：给每组保留可访问的公网 IP / 端口用于预览。

### 方向 2：把基础能力提前准备好

- 如果方便的话，希望环境里能提前接入豆包大模型。
- 如果方便的话，也希望能提前接入生图模型。
- `git` 如果能预装会更理想，因为东西会放到github或者gitlab。
- 最理想的状态是参与者整体无需登录或只需简单登陆，拿到链接即可开始。

## 5. 这两张地图大概的工程与技术选型

为了方便资源匹配，这里补充一下当前工程的粗略情况：

- 我们已经有完整的 `two-maps` 工程模板。
- 这是一个 `pnpm workspace` 的 monorepo。
- 当前有一个合并的 `Nuxt 3` 网页应用作为统一 web 入口，也保留了按地图拆分的网页工程脚手架。
- 浏览器侧主要是 `Nuxt 3 + TypeScript`。
- 地图能力目前基于 `Leaflet`，并带有部分 3D globe 能力。
- 两张地图各自还有一个 `Remotion` 视频工程，用于最终视频化输出。
- 共享的数据结构和工具在 `shared` 包里统一维护。
- 当前工程默认是 `Node + pnpm` 启动后，通过网页进行实时预览，因此网页预览能力对现场非常关键。

## 6. 我们希望对方先给到什么反馈

我们希望先和伙伴一起判断两件事：

1. 按这个活动形式来看，以上设想是否可行。
2. 如果方向合适，大概需要匹配什么样的产品形态和现场资源配置。
